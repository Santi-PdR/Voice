# Great Sage Voice / Rafael

Forge 1.20.1 mod that adds a compact cinematic Rafael / Great Sage analysis HUD, contextual event reactions and optional synthetic speech generated by the Minecraft server.

## v1.1 architecture: no Python, no localhost, no extra terminal

The old runtime model depended on `ai_backend/main.py`, FFmpeg and `http://localhost:8000`. That design was unsuitable for a real client/server mod because every host had to keep a separate Python process alive and clients depended on a reachable audio URL.

v1.1 moves the complete runtime pipeline into the Forge server:

```text
Minecraft event
   -> Forge server snapshots event data
   -> optional OpenAI Responses analysis
   -> server-side TTS (OpenAI or ElevenLabs)
   -> WAV/PCM audio held in memory
   -> Forge S2C packet (text + emotion + audio bytes)
   -> client HUD + Java Sound playback
```

Players only need the mod. No Python installation, FastAPI process, FFmpeg process, open localhost port or public audio web server is required.

API keys remain on the server and are never serialized to clients.

## Voice profile

The default OpenAI setup uses `gpt-4o-mini-tts`, the `marin` built-in voice and a server-configurable direction designed for an original synthetic system voice: calm, adult feminine, clear, controlled, analytical, slightly ethereal and concise.

The project does **not** ship or automatically clone a real dub actor's voice. If an exact human voice likeness is ever used, the server owner must have the necessary authorization and use a provider flow that verifies consent. For a closer fictional-system aesthetic without cloning an actor, ElevenLabs Voice Design can be used to create an original voice and its resulting Voice ID can be placed in the server config.

The HUD can display `SYNTH VOICE` while generated speech is active.

## Installation

Install the same JAR on the Forge 1.20.1 server and every client that should receive the Rafael HUD/audio.

On an integrated single-player world, the game acts as both server and client, so the same server-native architecture is used automatically.

## Server configuration

Forge creates:

```text
world/serverconfig/great_sage_voice-server.toml
```

Important options:

```toml
enableAI = true
enableGeneratedResponses = true
enableVoice = true
ttsProvider = "openai"

[OpenAI]
openAiApiKey = ""
openAiResponseModel = "gpt-5.6-luna"
openAiTtsModel = "gpt-4o-mini-tts"
openAiVoice = "marin"
```

For a dedicated host, prefer setting `OPENAI_API_KEY` in the host/environment instead of writing the secret into a file. If that is not available, `openAiApiKey` can be configured in the server-only TOML. Never distribute that server config with a modpack.

If the key is missing, Rafael keeps working with deterministic local text and UI effects; generated AI text and OpenAI voice fall back safely instead of crashing the game.

### ElevenLabs alternative

```toml
ttsProvider = "elevenlabs"

[ElevenLabs]
elevenLabsApiKey = ""
elevenLabsVoiceId = "YOUR_AUTHORIZED_OR_DESIGNED_VOICE_ID"
elevenLabsModel = "eleven_multilingual_v2"
```

`ELEVENLABS_API_KEY` can also be supplied by the server environment. The mod requests 24 kHz PCM and wraps it as a WAV before sending it to the client.

## Client configuration

Forge creates:

```text
config/great_sage_voice-client.toml
```

Client options include HUD scale, typewriter speed, maximum HUD lines, independent voice/UI volumes and synthetic-voice disclosure.

## Commands

```text
/rafael test <message>   Contextual manual analysis + TTS test
/rafael voice            Short voice pipeline test
/rafael status           Server-native/provider status without exposing secrets
```

## Automatic events

Configurable reactions include:

- player login/synchronization
- death and death cause
- respawn
- critical health threshold
- game mode changes
- advancements
- item tosses (off by default because they are noisy)

A per-player/per-event cooldown prevents event spam and overlapping provider requests. Death and manual tests can bypass the cooldown.

## Reliability improvements in v1.1

- server thread data is snapshotted before asynchronous provider calls
- provider work runs on dedicated daemon workers instead of the common ForkJoin pool
- result delivery returns to the Minecraft server thread before locating/sending to the player
- HTTPS-only provider endpoints
- bounded HTTP response sizes
- bounded voice packet sizes
- 32-entry server TTS cache to reduce duplicate cost and latency
- graceful local fallback if AI or TTS fails
- protocol v2 carries WAV bytes directly instead of unsafe/public audio URLs
- client stops the previous voice before a new one starts to prevent overlapping speech
- Java Sound errors are logged with their real cause
- HUD scaling no longer pushes elements off-screen
- dynamic response panel height/line wrapping
- real fade animation (the previous alpha calculation was not applied)
- FPS-independent orbital particle motion
- actual thin ray/ring lines instead of rectangular `fill` rays
- emotion-aware HUD accents for critical, milestone and synchronization states
- separate voice and UI-effect volumes

## Build

Java 17 is required.

Windows:

```powershell
.\gradlew.bat clean build --no-daemon
```

Linux/macOS:

```bash
./gradlew clean build --no-daemon
```

The repository also includes GitHub Actions CI using Java 17 and Gradle 8.3.

## Security

Do not put provider API keys in Java source, resources, commits, client config or chat commands. Keys belong only to the server environment or the server-only config.

See `SECURITY.md` and `docs/VOICE_SETUP.md` for operational details.
